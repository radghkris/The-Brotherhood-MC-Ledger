# Thread 2: Ledger — Plan

Scope (from the design doc): entries, running balance, void, audit log, CSV export, ledger screen.

Decisions (ambiguities resolved):
- Migration is `0006_entries.sql` (0002-0005 are reserved for other threads).
- `haul_id` / `loan_id` are plain nullable integers (no FK) because those tables arrive in later threads.
- Pickers need members, so a read-only `GET /api/entries/members` is added here; the Roster thread owns real member CRUD.
- "Excel export" is delivered as CSV (opens in Excel). Cells starting with `= + - @` are prefixed with `'` to block formula injection.
- Overdraft: a withdrawal that would take the balance below $0 returns 409 unless an admin sends `confirmOverdraft: true`.
- Everyone logged in can view the ledger; officers+ add entries; only admins void.

Tasks
1. Migration + pure running-balance logic (`server/src/ledger.ts`) with tests.
2. Entries API: list (filters), create (validation, overdraft rule, audit), void (admin, reason, audit) with tests.
3. CSV export with tests.
4. Ledger page (table, filters, add form, void, export) replacing the placeholder.
5. `npm test` and `npm run build`, PR.
